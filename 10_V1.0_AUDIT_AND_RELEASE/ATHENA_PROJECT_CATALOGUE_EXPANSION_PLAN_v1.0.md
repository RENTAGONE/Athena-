# ATHENA Project Catalogue — Expansion and Reconciliation Plan v1.0

**Current position:** Wave 09 authored 18 detailed blueprints (6 personal-use, 6 product/business-foundation, 6 intrinsic/for-its-own-sake). It also mapped 33 legacy project entries provisionally/conditionally. Earlier 9-project portfolio and 9-project traceability baselines are present in the Wave 09 validation snapshot. These counts must not be added together as if they were unique projects until IDs and overlap are reconciled.

## Non-negotiable project classes

1. **Personal-use:** solves an actual personal problem; no customer, sale or public release required.
2. **Product/business-foundation:** has a credible user/value/evidence/operations path and can later be packaged or sold; sales are not guaranteed.
3. **Intrinsic/for-its-own-sake:** exploration/creation without utility or commercial requirement.

Teamwork is a delivery format, not a fourth class. Project completion does not grant module mastery.

## Expansion method

1. Inventory every project source and preserve original IDs.
2. Deduplicate by intent and deliverable, not title similarity alone.
3. Map each project to a class with rationale and conditional status where intent is unclear.
4. Build coverage matrix across all 18 disciplines, module objectives, micro-skills and assessment evidence.
5. Identify project gaps: missing disciplines, no beginner entry, no phone-only version, no low-cost version, no individual evidence, unsafe or legally complex tasks.
6. Add projects only where they teach meaningful integration not already covered; avoid catalogue bloat.
7. For each new blueprint require audience/problem or intrinsic question, constraints, milestones, artifacts, acceptance criteria, evidence, rubric, safety/privacy, low-resource options and transfer iteration.
8. Pilot project usability only after the app supports project selection, evidence capture and progress review.

## Proposed expansion batches

- **Batch A — Foundation breadth:** one beginner-friendly project per discipline or justified discipline cluster; focus on low-cost, phone-capable, safe, demonstrable outcomes.
- **Batch B — Cross-discipline integration:** projects with genuine multi-domain dependencies and individual evidence.
- **Batch C — Advanced/specialist:** deeper T0–T5 projects with explicit entry criteria and qualified supervision where needed.
- **Batch D — Personal/product/intrinsic pathways:** multiple projects within each class at different levels, without forcing commercialisation of personal or intrinsic work.

## Acceptance criteria

No project is added solely to hit a count. The catalogue is adequate when every project has a unique stable ID, explicit class, objective links, evidence/rubric, safety/ethics boundaries, low-resource alternative, and a distinct reason to exist; coverage gaps and intentional absences are documented.
