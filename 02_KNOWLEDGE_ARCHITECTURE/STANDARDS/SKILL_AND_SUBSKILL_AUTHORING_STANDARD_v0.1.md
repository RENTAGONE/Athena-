# Skill and Subskill Authoring Standard v0.1
Status: Draft. Applies across all 18 disciplines.

## 1. What counts as a skill
A skill is a demonstrable capability: the learner can perform an action to a stated quality under identifiable conditions. A topic, interest, tool name, resource, personality trait or vague aspiration is not by itself a skill.

## 2. Hierarchy and canonical ownership
Use `Discipline -> Domain -> Skill family -> Skill -> Subskill` as the default navigational hierarchy. Do not force every concept into this tree: concepts and objectives can cross-link to multiple skills. Give each skill one canonical primary discipline based on its principal performance outcome. Cross-disciplinary application is represented by typed relationships, not duplicate copies.

## 3. Skill record minimum
Every candidate skill needs: stable ID; concise title; outcome statement; canonical discipline; domain/family mapping when known; status; evidence types; safety class; source/provenance; content version. Add subskills only when they represent distinct teachable/performance components.

## 4. Outcome statement
Use: action + object + conditions/context + quality criterion. Prefer verbs such as calculate, explain, construct, diagnose, compare, perform, design, evaluate, communicate and adapt. Avoid `know` or `understand` without observable evidence.

## 5. Avoiding taxonomy bloat
Do not create a new skill for every tool, chapter, app, exercise, context or difficulty level. Split a skill only when the sub-capabilities have distinct outcomes, assessment needs, prerequisites or practice protocols. Merge near-duplicates; preserve aliases and migration history.

## 6. Difficulty and progression
Represent challenge across dimensions (complexity, novelty, independence, precision, constraints, consequence), not a single universal beginner/intermediate/advanced label. Skill records describe the capability; learner-specific progression belongs in competency/evidence records.

## 7. Review gates
Draft -> review -> approved. Review checks: distinctness, observable outcome, canonical ownership, prerequisite validity, evidence alignment, safety, resource quality, duplicate detection and transfer claims. Approval does not mean the learner has mastered the skill.
