# ATHENA Foundational Curriculum — Master Working Draft

**Purpose:** Establish the shared capabilities that make later learning across ATHENA's 18 disciplines faster, more independent, more accurate, and more transferable.  
**Status:** Substantive working curriculum; requires review and learner diagnostic before approval.  
**Design:** Non-linear, placement-based, evidence-led. A learner can test out of material by demonstrating the relevant outcomes.

## How a unit is completed

A unit is not complete merely because its explanation was read. The learner should be able to: (1) retrieve the central idea without looking, (2) explain it accurately, (3) perform the relevant procedure or solve a new problem, and (4) apply it in a different context where appropriate. Evidence is stored separately from the content. A weak attempt creates a useful next step; it does not erase earlier evidence.

# FND-01 — Learning how to learn

**Purpose:** Build reliable methods for acquiring, checking, retaining, and applying knowledge. This is a meta-skill pathway, not a productivity-hack collection.

## Module 1.1 — What learning is and how to diagnose it

**Core model:** Learning is a relatively durable change in what a person can retrieve and do, not the temporary feeling of familiarity while material is visible. Performance during practice can be inflated by hints, rereading, copying, and immediate repetition. Learning must therefore be checked after a delay and without the original cues.

**Concepts:** exposure vs learning; fluency illusion; retrieval; transfer; prior knowledge; cognitive load; novice/expert differences; diagnostic assessment.

**Objectives**
- Distinguish exposure, immediate performance, durable retention, and transfer using concrete examples.
- Identify when a learner's confidence is based on recognition rather than unaided recall.
- Complete a short diagnostic that separates prerequisite gaps from unfamiliar wording.
- Select an appropriate next step: explain, practise, retrieve, seek feedback, or revisit a prerequisite.

**Worked example:** A learner follows a video and reproduces a Python loop while the video is paused. This demonstrates guided performance, not yet independent competence. A stronger test is to close the video, write a loop for a changed problem, explain the iteration variable, and solve a similar task the next day.

**Practice:** For three recently studied topics, write (a) what was studied, (b) what can be recalled with no notes, (c) what can be explained, and (d) what can be done in a changed example. Mark uncertainty rather than guessing.

**Assessment:** Given four study scenarios, classify the evidence level and propose a diagnostic check. Success: all four classifications are defensible and each proposed check measures the claimed ability rather than familiarity.

**Misconceptions:** More time automatically means more learning; feeling easy means mastery; one quiz proves durable knowledge; struggling always means the method is bad.

## Module 1.2 — Attention, working memory, and cognitive load

**Core model:** Working memory is limited. Learning is affected by the complexity of the task, the learner's prior knowledge, interruptions, and the way information is presented. Chunking works when meaningful relationships have been learned; arbitrary grouping does not magically increase capacity.

**Concepts:** attention; working-memory limits; intrinsic/extraneous/germane load as a useful instructional model; chunking; prior knowledge; task switching; environmental distraction; sleep and consolidation (without treating any single sleep claim as a guaranteed outcome).

**Objectives**
- Explain why a dense unfamiliar explanation can overload a novice.
- Rewrite a confusing procedure into ordered, testable steps without removing essential reasoning.
- Identify avoidable split-attention and task-switching costs in a study setup.
- Use worked examples before gradually reducing support on a genuinely new procedure.

**Practice:** Take a multi-step task (e.g. solving a linear equation or debugging a short script). Separate the goal, known information, operations, and check. Then solve a parallel task without the scaffold.

**Assessment:** Compare two instructional layouts and justify which better supports a novice, identifying at least one trade-off. Success: reasoning refers to task complexity and prior knowledge, not aesthetic preference alone.

**Misconceptions:** Multitasking is efficient; all learners have the same fixed attention span; chunking means memorising arbitrary groups; removing all difficulty improves learning.

## Module 1.3 — Retrieval, spacing, interleaving, and feedback

**Core model:** Retrieval practice strengthens access to knowledge and reveals gaps. Spacing distributes retrieval over time. Interleaving mixes related problem types so the learner must identify which method applies. Feedback is useful when it is specific, timely enough to guide correction, and followed by another attempt.

**Concepts:** free recall; cued recall; practice testing; spacing; interleaving; elaboration; feedback; desirable difficulty; calibration; error correction.

**Objectives**
- Create retrieval prompts that require generation rather than recognition.
- Explain why a spaced review differs from massed repetition.
- Interleave two or more similar problem types and identify the cue that selects the method.
- Use feedback to correct an error and then complete a fresh problem independently.
- Rate confidence before checking an answer and compare confidence with correctness.

**Practice:** Build a five-prompt retrieval set for a concept. Use one free-recall prompt, one explain-why prompt, one application prompt, one discrimination prompt, and one transfer prompt. Attempt before opening notes.

**Assessment:** Given a topic and learner performance history, design a short review sequence with a rationale. Success: schedule includes retrieval, spacing, feedback and an application check; it does not assume a universal fixed interval.

**Misconceptions:** Rereading is the same as retrieval; flashcards teach every kind of skill; spacing means a fixed number of days for everyone; interleaving means random chaos.

## Module 1.4 — Elaboration, mental models, deliberate practice, and transfer

**Core model:** Elaboration connects new ideas to accurate prior knowledge. Mental models help predict and explain. Deliberate practice targets a specific weakness with clear criteria and feedback. Transfer requires recognising which underlying principle applies in a new context; it is not guaranteed by superficial similarity.

**Concepts:** self-explanation; analogy and its limits; causal model; worked example fading; deliberate practice; transfer distance; near/far transfer; metacognition; reflective error analysis.

**Objectives**
- Explain a concept in one's own words and connect it to a previously learned concept without distorting either.
- Build a simple causal or procedural model that predicts an outcome.
- Turn a vague goal (“get better at coding”) into a measurable practice target.
- Identify surface similarities and deep structural similarities between two tasks.
- Complete a transfer task and explain which principle was reused and what had to change.

**Practice:** Choose one skill, identify its weakest observable component, design a 15–25 minute focused practice block, obtain feedback, and repeat with a changed example. Record the error and correction.

**Assessment:** Solve a problem in an unfamiliar context using a previously studied principle. Success: the learner identifies the relevant principle, maps it to the new context, states a limitation of the analogy, and checks the result.

**Misconceptions:** A catchy analogy is always accurate; transfer happens automatically; deliberate practice is simply doing many repetitions; reflection without evidence improves performance.

# FND-02 — Mathematics and quantitative foundations

**Purpose:** Build numerical fluency and the language needed for science, engineering, finance, computing, and evidence evaluation. This pathway is diagnostic and adaptive: demonstrated competence is not repeated for the sake of a linear syllabus.

## Module 2.1 — Number sense, place value, and operations

**Core model:** Numbers represent quantities and relationships. Place value makes our base-ten notation positional: each place is ten times the value of the place to its right. Addition combines quantities, subtraction compares or finds a difference, multiplication scales or groups, and division partitions or measures how many groups fit.

**Concepts:** natural/whole/integer/rational numbers; place value; estimation; number line; operation meaning; inverse operations; order of operations; divisibility; factors and multiples.

**Objectives**
- Read, write, compare, order, and locate whole numbers and integers on a number line.
- Explain the role of each digit in a multi-digit base-ten number.
- Select an operation from the meaning of a word problem rather than keyword matching.
- Estimate an answer before calculating and use the estimate to detect an unreasonable result.
- Apply order of operations and explain why grouping changes the result.

**Worked example:** 3 packs of 8 notebooks means 3 × 8, not 3 + 8. If 24 notebooks are shared equally among 6 people, 24 ÷ 6 = 4 each. Multiplication and division reverse each other in these contexts.

**Practice:** Use a number line to compare negative temperatures; estimate a grocery total; calculate equal sharing and repeated groups; explain the meaning of each operation in a new context.

**Assessment:** Solve a mixed set of contextual problems, show the operation choice, estimate first, and verify by an inverse operation where possible. Success: correct result plus a valid model and reasonableness check.

**Misconceptions:** Multiplication always makes bigger; subtraction always makes smaller; division always makes smaller; the equals sign means “write the answer next”.

## Module 2.2 — Fractions, decimals, percentages, and ratio

**Core model:** Fractions, decimals, and percentages are different representations of rational numbers. A ratio compares quantities multiplicatively. Equivalent representations preserve value; the appropriate representation depends on the problem.

**Concepts:** numerator/denominator; unit fractions; equivalent fractions; common denominator; decimal place value; percent as per hundred; ratio; rate; unit rate; proportion; scale.

**Objectives**
- Represent a fraction visually, on a number line, and as a division statement.
- Generate and justify equivalent fractions.
- Convert common fractions, decimals, and percentages and explain the conversion.
- Compare quantities using a common unit or a unit rate.
- Solve proportional problems while distinguishing additive from multiplicative comparison.

**Worked example:** 3/4 = 0.75 = 75%. If a recipe uses 3 cups for 4 people, the unit rate is 0.75 cup per person; for 8 people, scale both quantities by 2 to use 6 cups.

**Practice:** Compare discounts with different base prices; scale a recipe; calculate a percentage increase and decrease; identify when two quantities are not proportional.

**Assessment:** Solve a multi-step shopping/recipe/scale problem and explain the representation chosen. Success: units are consistent, the base for each percentage is explicit, and the proportional relationship is justified.

**Misconceptions:** A larger denominator always means a larger fraction; percent change is independent of the starting value; ratio is just subtraction; 20% off followed by 20% on returns to the original price.

## Module 2.3 — Signed numbers, exponents, roots, and algebraic thinking

**Core model:** Negative numbers extend the number system to represent direction, debt, and values below a reference point. Exponents represent repeated multiplication for integer powers; roots reverse suitable power operations. Algebra uses symbols to express general relationships and unknown quantities.

**Concepts:** integers; absolute value; signed operations; powers; squares/cubes; square roots; order of operations; variables; expressions; equality; substitution; simplifying; one-step and multi-step equations; inequalities; formula rearrangement.

**Objectives**
- Perform integer operations using number-line reasoning and sign rules.
- Evaluate simple powers and roots and distinguish a square from a square root.
- Translate a verbal relationship into an algebraic expression.
- Simplify expressions by combining like terms while preserving equality.
- Solve linear equations and verify by substitution.
- Explain the difference between an expression, an equation, and an inequality.

**Worked example:** If a phone plan costs 120 taka plus 8 taka per day, the cost for d days is C = 120 + 8d. For 5 days, C = 160. If the total is 200, solve 120 + 8d = 200, giving d = 10; substitution checks the result.

**Practice:** Evaluate powers; estimate square roots between nearby perfect squares; translate short scenarios into expressions; solve and verify equations; identify invalid steps in a worked solution.

**Assessment:** Model a real situation with a linear equation, solve it, check it, and state what the variable and solution mean in context. Success: correct model, valid transformations, verification, and interpretation.

**Misconceptions:** A variable is always an unknown fixed number; changing sides changes a sign by magic; √(a+b) = √a + √b; exponentiation is repeated addition.

## Module 2.4 — Measurement, geometry, graphs, probability, and data literacy

**Core model:** Measurement assigns numbers and units to quantities. Geometry studies spatial relationships. Graphs represent relationships and data; probability quantifies uncertainty under a model. Statistical summaries describe data but do not automatically explain causes.

**Concepts:** SI units; unit conversion; perimeter/area/volume; angle; triangle properties; coordinate plane; tables and graphs; mean/median/mode/range; sampling; variability; probability; independent/dependent events; correlation vs causation.

**Objectives**
- Choose a suitable unit and convert within a consistent measurement system.
- Distinguish perimeter, area, and volume and select the correct model.
- Read coordinates and interpret the axes, scale, and units of a graph.
- Select mean or median based on distribution and outliers.
- Calculate simple probabilities and identify assumptions such as equally likely outcomes.
- Explain why correlation alone does not establish causation.

**Practice:** Measure a room or object; compare two data sets with different outliers; graph a small data set with labelled axes; run a simple repeated random experiment and compare observed frequencies with expected probability.

**Assessment:** Interpret a short data report and identify what can and cannot be concluded. Success: calculations are correct, units and sample context are stated, uncertainty is acknowledged, and causal claims are not overstated.

**Misconceptions:** The average is always representative; a graph proves a trend regardless of scale; larger samples remove all bias; a likely event is guaranteed; area and perimeter are interchangeable.

# FND-03 — Logic and analytical reasoning

**Purpose:** Improve the ability to distinguish claims from evidence, test arguments, reason under uncertainty, and solve unfamiliar problems without relying on confident-sounding language.

## Module 3.1 — Claims, premises, conclusions, and argument structure

**Core model:** An argument is a set of premises offered in support of a conclusion. A claim can be true or false independently of whether the argument for it is valid. Strong reasoning makes assumptions visible and connects evidence to the conclusion.

**Concepts:** claim; premise; conclusion; inference; validity; soundness; deductive/inductive/abductive reasoning; hidden assumption; counterexample; burden of proof.

**Objectives**
- Extract premises and conclusion from ordinary prose.
- Distinguish validity (structure) from truth of premises.
- Identify an unstated assumption and test whether the argument depends on it.
- Construct a counterexample to an overgeneralised claim.
- Rewrite an unclear argument into explicit, testable statements.

**Practice:** Analyse short claims from advertisements, online debates, and science explanations. Label evidence separately from opinion and identify what additional information would change the conclusion.

**Assessment:** Evaluate a short argument, reconstruct its form, identify one hidden assumption, and provide a counterexample or supporting evidence. Success: criticism addresses the reasoning rather than attacking the speaker.

## Module 3.2 — Propositional logic, conditionals, and quantifiers

**Core model:** Logical connectives combine propositions. A conditional “if P, then Q” is not equivalent to “if Q, then P”. Quantifiers express whether a statement applies to all, some, or none of a defined set.

**Concepts:** AND/OR/NOT; implication; biconditional; truth table; necessary/sufficient conditions; converse/inverse/contrapositive; universal/existential quantifiers; scope; contradiction.

**Objectives**
- Evaluate simple compound statements using truth tables.
- Distinguish a conditional from its converse and contrapositive.
- Identify necessary and sufficient conditions in everyday statements.
- Translate simple “all”, “some”, and “none” claims into precise language.
- Detect contradictions and quantifier shifts in arguments.

**Practice:** Test statements such as “If a number is divisible by 4, it is even” and its converse; construct examples; rewrite vague claims with explicit quantifiers.

**Assessment:** Given a set of conditional statements, identify valid implications and invalid converse reasoning. Success: every answer is supported by a truth table, definition, or counterexample.

## Module 3.3 — Causality, systems, and decision reasoning

**Core model:** A system contains interacting parts and feedback. Observed association may arise from direct causation, reverse causation, confounding, selection effects, or coincidence. Decisions require comparing options against goals, constraints, probabilities, and consequences.

**Concepts:** causal mechanism; confounder; feedback loop; stock/flow; base rate; expected value; opportunity cost; reversibility; sensitivity analysis; second-order effects.

**Objectives**
- Draw a simple causal diagram for a real-world claim.
- Identify at least one plausible confounder or reverse-causality explanation.
- Distinguish a reinforcing feedback loop from a balancing loop.
- Compare choices using explicit criteria and opportunity cost.
- Perform a simple expected-value calculation and explain its limitations.

**Practice:** Analyse why a product's sales rose; map a feedback loop in a habit or business process; compare two project options with different costs and uncertain outcomes.

**Assessment:** Produce a one-page decision memo with assumptions, options, risks, expected consequences, and a condition that would trigger revisiting the decision. Success: assumptions and uncertainty are explicit.

## Module 3.4 — Bias, uncertainty, and calibrated judgment

**Core model:** Human judgment uses shortcuts that are sometimes efficient and sometimes systematically misleading. Calibration means confidence corresponds reasonably well to actual accuracy over repeated judgments. Uncertainty should be represented, not hidden.

**Concepts:** confirmation bias; availability; anchoring; survivorship bias; selection bias; regression to the mean; base rates; probability language; confidence calibration; falsifiability.

**Objectives**
- Identify common reasoning biases in examples without using labels as insults.
- Apply base-rate information before interpreting a vivid case.
- State a prediction with a probability or confidence range and later score its calibration.
- Identify what evidence could falsify a hypothesis.
- Separate known facts, estimates, assumptions, and unknowns.

**Practice:** Make five low-stakes predictions with confidence ratings, record outcomes, and review whether confidence was systematically too high or low.

**Assessment:** Evaluate a persuasive but weak claim, identify the missing base rate or selection issue, and propose a fair test. Success: critique is specific and a plausible disconfirming result is named.

# FND-04 — Research and information literacy

**Purpose:** Enable independent research while resisting misinformation, fabricated references, search-engine ranking effects, and unsupported claims.

## Module 4.1 — Turning curiosity into a researchable question

**Core model:** A useful question defines a topic, scope, population or context, and the kind of answer sought. Broad curiosity is valuable, but research requires boundaries and terms that can be searched and tested.

**Objectives**
- Convert a broad topic into a focused question.
- Distinguish descriptive, explanatory, comparative, evaluative, and causal questions.
- Define key terms and scope before searching.
- Generate alternative search terms, synonyms, and narrower subquestions.

**Practice:** Convert “Is AI good?” into three distinct research questions with different scopes and evidence needs.

**Assessment:** Submit a question brief containing the main question, definitions, scope, subquestions, and what would count as a useful answer.

## Module 4.2 — Search strategy and source evaluation

**Core model:** Search engines retrieve and rank documents; they do not certify truth. Source evaluation considers author expertise, publisher, evidence, methods, date, incentives, transparency, and corroboration. Primary sources are not automatically correct, but they allow inspection of original evidence.

**Concepts:** keyword search; phrase search; Boolean operators; source type; primary/secondary/tertiary source; authority; relevance; currency; methodology; conflict of interest; corroboration.

**Objectives**
- Build a search plan using synonyms and Boolean operators.
- Distinguish source types and choose sources suited to the question.
- Evaluate a source's expertise, evidence, date, incentives, and limitations.
- Trace a claim to its underlying source rather than repeating an unattributed summary.
- Corroborate important claims with independent evidence.

**Practice:** Research one technical claim using an official specification, a textbook or review, and an independent explanation. Record what each source can and cannot establish.

**Assessment:** Produce an annotated source set with a relevance and reliability rationale for each item. Success: source type and limitations are identified; no source is accepted solely because it ranks first.

## Module 4.3 — Evidence, citations, and synthesis

**Core model:** Evidence supports claims only to the extent that the method and data justify the inference. Synthesis compares sources and explains agreement, disagreement, and uncertainty; it is not a stitched-together list of summaries.

**Objectives**
- Separate a source's finding from the author's interpretation.
- Record enough bibliographic detail to relocate a source.
- Paraphrase accurately and distinguish paraphrase from quotation.
- Compare two sources' methods, populations, definitions, and conclusions.
- Write a synthesis that represents disagreement fairly.

**Practice:** Build a claim-evidence table with columns for claim, supporting source, evidence type, limitation, and confidence.

**Assessment:** Write a short evidence synthesis answering a focused question. Success: every material factual claim is traceable; limitations and disagreement are represented; quotations are clearly marked.

## Module 4.4 — Research design, data, and responsible use of AI

**Core model:** Research design must match the question. Observational data, experiments, interviews, and case studies answer different questions and have different limitations. AI can assist with search planning, explanation, and drafting, but outputs require verification and must not be treated as sources by themselves.

**Objectives**
- Match a question to a suitable descriptive, observational, experimental, or qualitative method.
- Identify sampling, measurement, confounding, and ethics risks in a simple study.
- Distinguish a result from a causal conclusion.
- Verify AI-generated factual claims against reliable sources.
- Record AI assistance transparently when required by the task or institution.

**Practice:** Design a small, low-risk observational study with a defined sample, variables, procedure, and limitations; do not collect sensitive data or involve people without appropriate permission.

**Assessment:** Submit a research protocol and critique. Success: question-method fit, ethical safeguards, operational definitions, and limitations are explicit.

# FND-05 — Communication and language foundations

**Purpose:** Build precise reading, writing, listening, explanation, and discussion skills across English and Bangla, including the ability to translate technical ideas without losing meaning.

## Module 5.1 — Comprehension and vocabulary architecture

**Core model:** Understanding a text requires decoding vocabulary, syntax, references, structure, and implied relationships. Technical vocabulary is best learned with definitions, examples, contrasts, and use in context—not isolated translation alone.

**Objectives**
- Identify a text's main claim, supporting points, and structure.
- Infer a word's likely meaning from context and verify it.
- Build a bilingual technical glossary with definition, context sentence, and common confusion.
- Distinguish a precise technical term from a loose everyday synonym.

**Practice:** Read a short science explanation, annotate unfamiliar terms, explain the paragraph in plain English, then create Bangla equivalents or explanatory phrases where appropriate.

**Assessment:** Explain a short technical passage to a beginner and answer questions about its key terms. Success: core meaning is preserved and no technical distinction is erased by translation.

## Module 5.2 — Sentence, paragraph, and structured writing

**Concepts:** sentence completeness; subject/verb relationships; clause; punctuation; paragraph unity; topic sentence; cohesion; transitions; audience; register; revision.

**Objectives**
- Write complete, unambiguous sentences.
- Build a paragraph around one controlling idea and supporting evidence.
- Organise an explanation in a logical sequence.
- Revise for precision, concision, and audience suitability.
- Distinguish an explanation, argument, report, instruction, and reflection.

**Practice:** Explain a scientific process in 150 words, then revise it to 80 words without losing causal steps.

**Assessment:** Produce a structured explanation with a clear claim, sequence, example, and conclusion. Success: a reader can reconstruct the idea without guessing missing steps.

## Module 5.3 — Listening, questioning, and oral explanation

**Concepts:** active listening; paraphrase; clarification; open/closed questions; turn-taking; verbal structure; signposting; audience adaptation; feedback.

**Objectives**
- Paraphrase another person's point before disagreeing.
- Ask a clarifying question that exposes an ambiguity.
- Explain a concept orally with a beginning, logical middle, and concise ending.
- Adapt vocabulary and detail to the listener's prior knowledge.
- Use feedback to improve a second explanation.

**Practice:** Give a two-minute explanation of a familiar concept; ask a listener what remained unclear; deliver a revised explanation.

**Assessment:** Explain a concept and respond to two follow-up questions. Success: accurate content, understandable structure, and evidence of listening rather than rehearsed monologue.

## Module 5.4 — Argument, rhetoric, and bilingual technical communication

**Concepts:** thesis; claim/evidence/reasoning; counterargument; rebuttal; ethos/pathos/logos as rhetorical lenses; audience; tone; translation choices; false equivalence; technical register.

**Objectives**
- Construct an argument with a claim, evidence, and explicit reasoning.
- Represent a counterargument fairly before responding.
- Distinguish persuasive force from evidential strength.
- Translate or explain a technical idea across English and Bangla while preserving definitions.
- Adjust tone and formality to purpose without sacrificing truthfulness.

**Practice:** Write a short position on a low-stakes issue, include the strongest opposing point, then produce a Bangla explanation of the same reasoning.

**Assessment:** Deliver a short evidence-based argument and answer a challenge. Success: accurate representation, relevant evidence, coherent reasoning, and fair treatment of disagreement.

# FND-06 — Digital and workflow foundations

**Purpose:** Give the learner operational competence with files, devices, information organisation, terminal tools, version control, and repeatable workflows. Tool-specific advanced material belongs in discipline pathways.

## Module 6.1 — Files, formats, paths, and backups

**Objectives**
- Explain the difference between a file, folder, path, extension, and application.
- Organise a small project with predictable folder names and a README.
- Distinguish source files, exported files, backups, and temporary files.
- Create and verify a backup by restoring a copy to a separate location.
- Recognise why a synced folder is not automatically a complete backup.

**Practice:** Create a small project folder, document its structure, export a copy, and verify that the copy opens.

**Assessment:** Recover a project from a backup and explain what was backed up and what was not. Success: the restored copy is usable and the process is reproducible.

## Module 6.2 — Data literacy, documents, and spreadsheets

**Objectives**
- Distinguish raw data, structured data, metadata, and derived results.
- Create a clean table with headers, consistent types, and explicit units.
- Use basic spreadsheet formulas and check them against a hand calculation.
- Identify missing values, duplicates, inconsistent units, and misleading chart scales.
- Document the origin and transformation of a data set.

**Practice:** Record a small non-sensitive data set, calculate totals and averages, graph it, and write a note describing limitations.

**Assessment:** Audit a flawed spreadsheet and correct its structure and formulas. Success: changes are justified and calculations are independently checked.

## Module 6.3 — Terminal, commands, and safe automation

**Objectives**
- Explain current working directory, absolute/relative paths, arguments, and exit status.
- Navigate folders and inspect files using basic shell commands.
- Run a script from a known directory and interpret errors.
- Distinguish a command's intended effect from its actual effect before executing destructive operations.
- Use small scripts to automate a repetitive, reversible task.

**Practice:** Create a folder tree, list files, copy a test file, run a simple script, and inspect the result. Use a sandbox directory; do not experiment with destructive commands on personal data.

**Assessment:** Complete a small terminal workflow from written instructions and explain each command's effect. Success: no unintended file changes and the final state matches the specification.

## Module 6.4 — Git, version control, and reproducible work

**Objectives**
- Explain repository, commit, branch, diff, remote, and merge at a conceptual level.
- Initialise or clone a practice repository and inspect its status.
- Make a small change, review the diff, commit with a meaningful message, and restore a previous version.
- Explain why secrets and credentials must not be committed.
- Write a minimal README with setup and usage instructions.

**Practice:** Use a throwaway repository to make two commits, compare them, and restore a file from an earlier commit.

**Assessment:** Demonstrate a traceable change history and recover from an intentional test mistake. Success: the learner can explain what changed, when, and how to reverse it.

# FND-07 — Scientific thinking and measurement

**Purpose:** Teach disciplined observation, measurement, hypothesis testing, model use, and interpretation of scientific evidence.

## Module 7.1 — Observation, models, and testable hypotheses

**Objectives**
- Distinguish direct observation, inference, interpretation, and speculation.
- Write a hypothesis that makes a testable prediction.
- Identify variables and define them operationally.
- Explain why a model is a useful representation rather than a perfect copy of reality.
- State what result would count against a hypothesis.

**Practice:** Investigate a simple non-hazardous phenomenon, record observations separately from explanations, and make a prediction.

**Assessment:** Submit a hypothesis and test plan with measurable variables and a possible disconfirming outcome.

## Module 7.2 — Measurement, units, uncertainty, and error

**Objectives**
- Select an appropriate instrument and unit for a quantity.
- Record measurements with sensible precision and units.
- Distinguish random variation from systematic error at an introductory level.
- Explain why repeated measurements can reveal variability but cannot automatically remove bias.
- Report a result without implying greater precision than the instrument supports.

**Practice:** Measure the same object several times with an available ruler or scale; compare readings and identify plausible sources of variation.

**Assessment:** Produce a short measurement report with method, units, readings, variation, and limitations.

## Module 7.3 — Variables, fair tests, and experimental design

**Objectives**
- Identify independent, dependent, and controlled variables in a simple investigation.
- Explain why changing several factors at once weakens causal interpretation.
- Design a fair comparison with a control or baseline where appropriate.
- Identify ethical, safety, and environmental constraints before conducting a test.
- Distinguish an experiment from an observational study.

**Practice:** Design a test of a low-risk physical or digital system using one planned change at a time.

**Assessment:** Critique an experiment with confounds and propose a stronger design. Success: the revised method isolates the intended factor and states remaining limitations.

## Module 7.4 — Evidence, scientific explanation, and revision

**Objectives**
- Construct a claim-evidence-reasoning explanation.
- Distinguish data from the model used to interpret it.
- Compare a result with a prediction and explain a mismatch.
- Revise a model when evidence conflicts with it rather than hiding inconvenient observations.
- Identify when a conclusion exceeds the data.

**Practice:** Write a claim-evidence-reasoning report from a small data set and include one alternative explanation.

**Assessment:** Present a conclusion with uncertainty and limitations. Success: each claim is supported by the reported evidence and alternative explanations are acknowledged.

# FND-08 — Project execution and synthesis

**Purpose:** Turn knowledge into finished, inspectable outputs. Projects are the integration mechanism across ATHENA, not a decorative badge or completion counter.

## Module 8.1 — Problem framing and requirements

**Objectives**
- Distinguish a symptom, a problem, a need, and a proposed solution.
- Identify users or stakeholders and their constraints without assuming their preferences.
- Write a problem statement and measurable success criteria.
- Separate requirements from implementation choices.
- Identify risks, dependencies, and unknowns before committing to a plan.

**Practice:** Select a small real problem and write a one-page brief containing context, affected user, constraints, requirements, non-goals, and success criteria.

**Assessment:** Review the brief with a stakeholder or independent reviewer. Success: requirements are testable and the proposed solution has not been mistaken for the problem itself.

## Module 8.2 — Planning, decomposition, and estimation

**Objectives**
- Decompose a project into deliverables and verifiable tasks.
- Identify task dependencies and critical blockers.
- Estimate effort using ranges and assumptions rather than false precision.
- Define a minimum viable test or prototype.
- Replan when new evidence changes scope or feasibility.

**Practice:** Build a task tree and dependency map for a small project; mark uncertain estimates and the next action that reduces uncertainty.

**Assessment:** Explain the plan and identify the highest-risk dependency. Success: tasks have observable outputs and the plan includes a realistic feedback point.

## Module 8.3 — Build, test, feedback, and iteration

**Objectives**
- Produce a small working artifact against explicit acceptance criteria.
- Test normal, edge, and failure cases appropriate to the project.
- Record defects and distinguish severity from inconvenience.
- Obtain feedback and convert it into prioritised changes.
- Preserve a working version before a risky revision.

**Practice:** Build a small artifact (calculation tool, research brief, visual design, electronics simulation, or process improvement), test it, and revise once.

**Assessment:** Demonstrate the artifact against acceptance criteria and show evidence of at least one meaningful revision.

## Module 8.4 — Delivery, documentation, and reflection

**Objectives**
- Deliver an artifact with instructions sufficient for another person to inspect or use it.
- Record decisions, sources, assumptions, and known limitations.
- Compare outcomes against the original success criteria.
- Identify which knowledge transferred across disciplines and where it failed.
- Propose a concrete next iteration based on evidence.

# Diagnostic placement policy

1. Start with a short self-report only to identify familiarity and preferred language; never treat it as proof.
2. Use a small set of representative tasks spanning recall, explanation, procedure, and transfer.
3. If the learner succeeds independently and can explain the reasoning, offer a harder probe rather than forcing all beginner units.
4. If the learner succeeds only with hints, record supported performance and target the missing independent step.
5. If wording is the obstacle, rephrase or offer English/Bangla terminology support before concluding that the underlying concept is missing.
6. Place the learner separately by skill. A learner may be advanced in arithmetic, novice in statistics, and intermediate in algebra.
7. Reassess after meaningful instruction or new evidence. Placement is revisable and is not an identity label.
