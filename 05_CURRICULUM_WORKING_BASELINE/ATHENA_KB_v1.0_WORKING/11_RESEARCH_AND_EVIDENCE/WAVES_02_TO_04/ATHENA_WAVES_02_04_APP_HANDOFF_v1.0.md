## Import rules
1. Treat these as additive research/design artifacts. Do not overwrite existing canonical registries or protocols.
2. Keep all 156 candidates in DRAFT. Do not mark expert-reviewed, learner-validated or approved.
3. Do not import the 130 candidate extension proposals as canonical nodes. They are a review queue.
4. The Wave 04 JSON is a policy/design layer, not a calibrated scheduler. Implement explainable recommendation logic only; no automatic mastery.
5. Preserve evidence events immutably and maintain history when current performance lapses.
6. D4 pathways must not offer unsupervised practical training or self-certification.
7. Use the registry (156) as the inventory source. The catalogue markdown currently has 140 visible bullets and needs a later controlled regeneration/fix.

## Review timing
Expert review, owner approval and learner testing are deliberately deferred until the app is usable. App availability does not itself close those gates; it enables them to happen.

## Validation boundary
Structural counts, ID coverage, source-reference resolution and package integrity are testable now. Instructional efficacy, semantic correctness, user experience and retention calibration require later review and app-based evidence.
